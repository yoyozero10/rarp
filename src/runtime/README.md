# Runtime

server.ts owns a project lock and token-authenticated loopback HTTP control API. daemon.ts runs it independently of the CLI. process.ts supervises a worker-host process, parses bounded output, enforces timeout and cleans up the process tree. worker-host.ts keeps a parent alive for cleanup after Codex exits.

Phase 3 supports one explicitly dispatched task or automatic workflow at a time. workflow.ts owns worker/reviewer sequencing, feedback, maximum rounds and overall deadline. Cancellation stops the current process and prevents subsequent rounds. Review errors fail the task without rewriting the worker's submitted attempt. Phase 4 adds optional task worktrees, scope validation, commit/check evidence, verified sequential integration, durable request keys and explicit lease-gated crash recovery. Interrupted workers require inspected, explicit retry; interrupted reviews can resume against the preserved submitted commit. Integration conflicts remain in a separate worktree. Events support an after-ID cursor; side effects are not automatically replayed. Queue scheduling and interactive permission/input handling are not implemented. Stale locks are never automatically taken over; inspect processes before removing a lock.
